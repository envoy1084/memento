# Database and transactions

Drizzle RC uses the Effect PostgreSQL driver. All repositories resolve the private transaction context before falling back to Database. Nested TransactionService.run calls join the outer transaction. Expected domain failures remain domain failures; only SQL/Drizzle errors become DatabaseError.

Gift transitions, job enqueueing, and audit rows share a transaction. Workflow RPC/provider calls execute outside database transactions. The transaction journal deliberately holds a database lock while preparing and signing an operation, then broadcasts only after the encrypted operation commits. Jobs use PostgreSQL row locks with SKIP LOCKED, expiring leases, and a unique deduplication key. Completion uses the lease token to reject stale workers.

Identifiers shared with contracts are 32-byte hex values. Application timestamps are Unix milliseconds; policy and session deadlines are Unix seconds. Amounts are decimal strings at JSON boundaries and exact PostgreSQL numerics where arithmetic is needed.

Migrations are generated by Drizzle Kit and reviewed before committing. PGlite tests apply the checked-in migrations. PostgreSQL locking requires separate integration verification; PGlite does not model multiple connections.
